Confirmed Decisions

These choices are now reflected in the markdown plan. The checkboxes are just a review aid for your browser session.

Applied to plan
My recommendation now: run the plan engineering technical review, then use that feedback to make one final patch before CE work.
Batch 1 applied: architecture and privacy
  • Token links use hashed tokens, short expiry, rate limits, state checks, and safe renewal.
  • External contacts are modeled separately from household members and snapshotted on requests.
  • Helper token pages show compact source summary and selected evidence excerpts, not full source artifacts by default.
  • Household admin and internal admin correction access are separate roles with audit events.
  • Provider webhooks use event ids/idempotency keys to avoid duplicate side effects.
Batch 2 applied: data model and state
  • Card type is separate from attention flags and computed coverage state.
  • Coverage slots use an explicit state machine: needs coverage, requested, accepted, declined, cancelled, covered external.
  • Detected changes create confirmation records before overwriting critical covered-event fields.
  • External owners can reuse external contacts while preserving free-form text snapshots.
  • Readiness items can have lightweight ownership/completion without becoming generic chores.
Batch 3 applied: testing and evals
  • Default stack: Vitest, Supabase local testing where practical, Playwright, and lightweight accessibility checks.
  • Gemini extraction gets fixture-based evals, not just JSON schema tests.
  • RLS, helper token scope, internal admin access, source artifacts, and token replay get explicit security tests.
  • Provider webhooks and the Vercel Cron job runner get contract/behavior tests.
  • CE work must create a QA test plan artifact for routes, flows, edge cases, mobile checks, and eval commands.
Batch 4 applied: performance and ops
  • V0/friends upload limits: 10 MB per file and 5 files per source input.
  • Large files should upload directly to Supabase Storage or signed upload flow; Next.js routes handle metadata only.
  • Vercel Cron upgrade triggers: backlog, p95 extraction time, timeout rate, stale locks, and processing delay.
  • Admin ops view includes job health, extraction counts, storage estimate, webhook failures, failed sends, and correction activity.
  • Pre-cohort quota/compliance checklist covers Supabase, Vercel, Resend, Twilio sender/A2P/opt-out/cost, and Gemini.
  • Analytics properties use internal ids/coarse buckets and exclude private family/source details.
Engineering review wrap-up added
  • Markdown plan now includes what already exists, NOT in scope, failure modes, and parallelization lanes.
  • Review summary records scope accepted as-is, four batches resolved, and CE work as the next likely step.
  • The HTML remains a dashboard; the markdown plan is the implementation contract.

Risk Map

The biggest risks are trust, sequencing, and integration edges, not whether the broader product can eventually be built.

High attention
Risk Why it matters Mitigation in plan
AI extracts wrong details Bad times or locations break trust immediately. Source visibility, confidence, Needs Review, user editing, admin correction.
Sensitive family data exposure Family logistics may include private information. RLS, private storage, scoped tokens, consent warning, admin audit.
Helper token links expose too much context One-off helpers should not see full forwarded emails, PDFs, screenshots, or the household board. Render compact source summary and selected evidence excerpts by default; full artifacts require authenticated parent/admin access.
Webhook retries duplicate side effects Provider retries can create duplicate sources, cards, responses, or analytics events. Persist provider event ids/idempotency keys and enforce idempotent processing.
Simple Vercel job runner falls behind Extraction, nudges, or weekly summaries could lag. Use cron secret, small batches, locking, retries, stale lock recovery, visible admin job status, and upgrade if backlog grows.
Calendar write-back slows the core loop The aha moment does not require write-back. Keep connect/read/import optional in v1; write-back defaults to milestone 1.5.
Admin correction grows into operations tooling That would distract from validating automation and coverage. Gemini first pass, correction metrics, narrow admin surface, no queues or CRM behavior.
