# Phase 1 Manual Board Loop

## Problem Statement

Phase 0 has a protected shell and sample board. Phase 1 needs real household-scoped board data, manual card setup/editing, member/helper/child setup, and coverage slot state transitions without paste/upload/email intake or provider request links.

## Findings

- `/app` currently renders `sampleCards`.
- Phase 0 has household membership, consent, job infrastructure, auth, and RLS helpers.
- New Phase 1 tables need household isolation policies and server actions should use the authenticated Supabase client so RLS is exercised.

## Proposed Solutions

1. Add only the manual board schema and actions now.
   - Pros: validates board loop quickly, keeps Phase 2 clean.
   - Cons: source/extraction/request-link criteria remain deliberately unchecked.
2. Add all v1 schema upfront.
   - Pros: fewer later migrations.
   - Cons: higher review burden and accidental Phase 2 scope creep.

## Recommended Action

Use option 1. Build the complete manual board loop with household-scoped children, external contacts, cards, slots, readiness items, and audit events. Keep source inputs/request tables minimal enough for references and future phases, but do not build ingestion or provider flows.

## Acceptance Criteria

- [x] Household admins can add parent/helper members and children.
- [x] `/app` uses real household data instead of sample cards.
- [x] Manual cards can be created and edited.
- [x] Needs Attention and This Week are derived from shared attention/coverage logic.
- [x] Slot transitions support `needs_coverage`, `requested`, `accepted`, `declined`, `cancelled`, and `covered_external`.
- [x] "I'll cover it" assigns the signed-in household member.
- [x] "Mark already covered" requires a member/helper or free-form external owner.
- [x] RLS/policy tests cover key Phase 1 tables and owner requirements.
- [x] Required verification commands pass.
